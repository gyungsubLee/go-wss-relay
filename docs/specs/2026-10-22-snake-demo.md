# snake-demo.v1 게임 본문

이 계약은 검증 클라이언트의 뱀 전체 상태다. Snake.io APK의 실제 통신 규격이 아니다.
중계 서버와 공용 SDK는 본문을 해석하지 않는다. WSS 봉투는 Protobuf, 이 게임 본문은 UTF-8 JSON이다.

단일 원본은 client/src/demo/snake-state.ts다. client/scripts/check-snake.ts가 실제 소켓과 본문 검사를 수행한다.

| 필드 | 계약 |
|---|---|
| x, y | 0..1 좌표. 16비트 단위로 반올림 |
| lifeId | 1..64자 영숫자·하이픈 생명 식별자 |
| heading | -π..π 라디안, 소수 셋째 자리 |
| speed | 0..16 화면 정규화 거리/초, 소수 셋째 자리 |
| length | bodyPath의 점 개수, 1..64 |
| bodyPath | 머리부터 꼬리까지 전체 경로. 전송 값은 0..65535 좌표 쌍 |
| mass, score | uint32 |
| isAlive | 생존 여부 |
| shared | 공용 상태 권한자가 발표하는 revision·seed·ended |

32개 경로를 쓰는 현재 화면은 이동 중 최대 20 Hz로 전체 상태를 발표한다.
수신자는 이전 본문 없이 뱀 몸통을 복원한다. 모션과 보간은 client/src/demo/main.ts가 처리한다.
본문은 4096바이트를 넘지 않으며, NaN·범위 밖 좌표·잘못된 경로·불일치 길이는 거부한다.
사건은 별도 Event의 action=pulse와 임의 ID다. 사건은 뱀 전체 상태를 대신하지 않는다.

## 공용 상태 권한

권한자는 WSS 연결 전 HTTPS에서 확인한 로비 소유자다. FIFO도 배정된 로비에서 같은 값을 조회한다.
접속 순서·현재 연결 목록으로 권한자를 다시 선출하지 않는다.
최초 접속 전 예약 참가자는 Welcome 목록에 없을 수 있다. 이를 영구 이탈로 판단하지 않는다.
최초 접속은 최대 31초 동안 기다린다. 한번 참가를 확인한 뒤 목록에서 사라지면 영구 이탈로 처리한다.
권한자 이외 참가자의 shared는 무시한다. revision이 이전 값 이하인 공용 상태도 무시한다.
일시 단절 중에는 권한을 유지한다. 같은 참가자가 복귀하면 같은 권한과 새 연결 세대를 사용한다.
영구 PeerLeft 또는 권한자의 ended=true를 받으면 경기를 종료하고 명시적으로 퇴장한다.
권한자 자동 이전과 서버의 게임 판정은 제공하지 않는다.

## 실제 측정

2026-10-22 fixture 기준: 32개 경로 전체 상태 679바이트, 최대 64개 경로 1127바이트다.
16명 SyncSnapshot의 Protobuf 인코딩은 각각 11337바이트와 18507바이트였다.
이 측정은 해당 생명 ID·수치의 예시다. 실제 JSON 숫자 자릿수에 따라 크기가 변한다.
한도 검사는 매번 인코딩한 실제 바이트에 적용한다.

679바이트·방당 16명·20 Hz·200명에서 노드 송신 약 41.4 MB/s, p99 약 49.8 ms였다.
1127바이트·방당 16명·10 Hz·200명에서 송신 약 34.0 MB/s, p99 약 50.6 ms였다.
부하 도구는 같은 크기의 본문에 지연 측정 시각을 넣는다. 게임 JSON 디코딩·렌더링 비용은 이 서버 측정에 포함하지 않는다.

최대 64개 경로를 방당 16명이 20 Hz로 보내면 방 송신 4 MiB/s 예산을 넘을 수 있다.
해당 프로필은 10 Hz 또는 더 작은 경로 표현을 사용하고 대상 장비에서 다시 측정한다.
작은 100바이트 상태의 1000명 결과를 뱀 상태의 1000명 수용량으로 해석하지 않는다.
현재 CLI 초기 상한은 실제 뱀 상태로 검증한 200명이며, 노드별 전송 압력으로 신규 배정을 추가 차단한다.

## 2026-10-23 연결 복구

SDK는 연결 epoch로 이전 인증 갱신의 성공·실패·finally를 격리한다. HTTP의 기존 5초 제한은 본문 읽기까지 적용한다.
검증 화면은 재시도 가능한 조회 오류 뒤 750ms 후 다시 조회한다. 퇴장·취소·종료 후에는 이전 조회가 화면을 바꾸지 못한다.
실제 Chrome과 SDK 검사의 범위는 [구조 변경 증거](../evidence/v2/2026-10-23-structure-refactor.md)에 구분했다.
위 성능 수치는 2026-10-22 측정이다. 구조 변경 후 전체 부하를 다시 측정하지 않았다.
