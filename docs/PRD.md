# 웹·Android 공용 WSS 중계 서버 제품 요구사항

갱신일: 2026-10-23. v2 전용 구조와 로컬 검사를 마쳤다. Task 10 독립 리뷰와 전체 브랜치 리뷰를 마쳤다. 최종 I1 수정도 재리뷰에서 닫았다.
전체 5단계 목표는 진행 중이다. Android 실기기·무선 망·실제 Linux 배포·원격 CI 검증은 남아 있다.

## 목표

웹에서 개발한 TypeScript 게임과 Android WebView 앱이 같은 WSS 계약을 사용한다.
사용자는 로비 또는 FIFO 매칭으로 같은 중계 방에 접속한다.
서버는 참가자 권한과 방 소유권을 관리한다. 클라이언트는 게임 모션·보간·판정을 소유한다.

## 필수 동작

1. 게스트 또는 인증된 사용자의 식별자를 서버가 결정한다.
2. 로비 생성·참가·퇴장·준비·소유자 시작을 동시 요청에도 일관되게 처리한다.
3. 공개·비공개 로비와 호환 계약별 FIFO 매칭의 기존 업무 규칙을 보존한다.
4. 노드 예약 성공 후 배정을 확정하고 해당 참가자의 접속권만 반환한다.
5. 상태는 참가자별 전체 상태로 발표한다. 서버는 최신 대기 상태만 남긴다.
6. 사건은 제한된 큐로 전달하고 접수 여부를 알린다. 상대의 적용 완료는 보장하지 않는다.
7. 재접속은 같은 방 인스턴스에서 세대를 교체한다. HTTPS 권한 재확인으로 접속권을 재발급한다.
8. 웹과 Android의 중단·복귀, 늦은 메시지, 느린 수신자와 만료를 명시적으로 처리한다.
9. 방당·노드별 전송량과 자원을 계측하고 측정한 프로필에 맞춰 입장 상한을 정한다.
10. 활성 방 하나는 노드 하나만 소유한다. 증설·드레이닝·장애·배정기 재시작을 검증한다.

## 범위와 제한

게임 좌표·충돌·점수의 정당성은 중계 서버가 보장하지 않는다.
공용 게임 상태는 게임 계약이 지정한 발표자가 소유한다. 그 발표자의 영구 이탈 정책도 게임이 지정한다.
초기 분산은 배정기 하나와 중계 노드 둘 이상이다. 방 실시간 이동과 배정기 다중 작성자는 범위에 포함하지 않는다.
플레이어 상태와 진행 방은 노드 메모리에 둔다. 진행 상태를 다른 노드에 매 프레임 복제하지 않는다.

## 클라이언트

MinbWebKit 4.0을 고정 서브모듈로 소비한다. SDK는 Phaser와 게임 규칙에 의존하지 않는다.
SDK는 연결·인증·인코딩·Heartbeat·재접속·세대 검사를 담당한다.
검증 화면은 두 참가자의 좌표와 이벤트를 보여 준다. 렌더링과 네트워크 발표 빈도는 분리한다.
Android 디버그 산출물과 Play 출시 산출물을 구분한다. 실기기 검증은 데스크톱 검사로 대체하지 않는다.
