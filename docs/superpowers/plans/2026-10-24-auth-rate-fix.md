# 인증 대기와 정상 전송 제한 수정 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 인증 대기의 IP 독점을 막고 정상 200명의 전송 제한 오류를 해결한다.

**Architecture:** 기존 인증 자원 반환 경로에 IP별 동시 대기 수를 연결한다. 전송 제한은 거부 원인과 수신 시각을 측정한 뒤 공유 지점에서 수정한다.

**Tech Stack:** Go 1.26.10, 기존 `golang.org/x/time/rate`, 실제 TypeScript SDK, Python 측정 실행기.

**Spec:** `docs/handoffs/2026-10-24-auth-admission-rate-limit.md`와 사용자 승인 범위.

## 공통 제약

- 기존 작업 트리 `codex/wss-v2`에서 편집권을 인수한다. 이전 미커밋 증거를 보존한다.
- 전역 인증 상한 128개와 기본 바이트 예산을 유지한다. 새 의존성을 추가하지 않는다.
- 같은 호스트의 부하는 순차로 실행한다. 진단용 소스는 overlay로 분리한다.
- 기존 TLS 인증서를 검증한다. 토큰과 개인 키를 증거에 넣지 않는다.
- 사용자가 수정·검사·재시험을 승인했다. 승인 질문과 커밋은 추가하지 않는다.

## 검토 항목

- 프록시 주소 정규화와 위조 XFF: 기존 ClientIP를 사용하고 신뢰 프록시 회귀 검사를 추가한다.
- 인증 실패·취소·성공: IP별 대기 수와 전역 슬롯이 모두 반환되는지 검사한다.
- 인증한 같은 IP 200명: SDK 연결과 집중 재접속으로 확인한다.
- 수신 정지 뒤 정상 프레임 묶음: 진단 시각에 근거한 회귀 검사를 남긴다.
- 실제 남용 전송과 기본 바이트 예산: 차단을 유지하고 보안 검사로 확인한다.

### Task 1: 인증 대기 독점 방지

**Files:** `internal/relay/server.go`, 인증 회귀 검사 파일.

**Interfaces:** 기존 `ServeHTTP`와 `ClientIP`를 사용한다. 공개 API는 바꾸지 않는다.

- [x] 같은 IP의 미인증 연결 64개가 다른 IP의 인증을 막지 않는 검사를 작성한다.
- [x] 기존 구현에서 실패를 확인한다.
- [x] 기존 mutex로 IP별 대기 수를 관리한다. 전역 상한의 절반인 64개를 적용한다.
- [x] 기존 성공·실패 반환 경로에 감소와 0개 항목 삭제를 연결한다.
- [x] 경계·자원 반환·신뢰 프록시 검사를 실행한다.

### Task 2: 정상 전송 제한 진단과 수정

**Files:** `internal/relay/connection.go`, 전송 회귀 검사 파일, 근거가 요구하는 규약 문서.

**Interfaces:** 기존 readLoop와 상태 처리 경로를 사용한다. 오류 코드와 바이트 예산을 유지한다.

- [x] 진단 overlay에서 제한기 종류·수신 시각·잔여 토큰·쓰기 오류 원인을 기록한다.
- [x] 기존 200명 부하를 실행하고 거부 원인을 확정한다.
- [x] 방 잠금 대기 중 50ms 간격 상태 6개를 보내는 검사에서 기존 제한 오류를 확인한다.
- [x] 상태 제한은 초당 20개를 유지하고 순간 허용량을 6개로 바꾼다. 250ms 묶음 도착을 허용한다.
- [x] 전체 40개/s와 모든 바이트 예산을 유지한다. 기존 8개 연속 전송의 거부를 확인한다.
- [x] 규약에 250ms 수신 편차의 허용 범위와 그 한계를 기록한다. 자연 부하의 이전 오류 원인은 직접 재현하지 못했음을 구분한다.

### Task 3: 같은 조건의 재시험

**Files:** `docs/evidence/v2/2026-10-24-auth-rate-retest/`.

**Interfaces:** 이전 실행기를 재사용한다. 새 소스·바이너리 해시와 실행 옵션을 함께 저장한다.

- [x] 현재 소스로 서버와 Go 발생기를 다시 빌드한다.
- [x] `go test -race -count=1 ./...`와 `go vet ./...`를 실행한다.
- [x] Go 진단과 기존 조건을 순차 실행한다. 추가 느린 수신 조건의 실패를 보존하고 200명 10Hz 60초를 별도로 마친다.
- [x] 실제 SDK 200명 20Hz·10Hz를 각각 실행한다. 공개 API와 집중 재접속도 포함한다.
- [x] 보안 검사와 방·연결·예약 슬롯 회수를 확인한다.
- [x] 독립 코드 검토 후 이전 결과와 한계를 보고한다.

실행 결과: 기존 SDK 두 조건과 Go 11개 조건을 통과했다. 추가 20Hz 느린 수신 조건의 실패를 보존했다.
200명·20Hz·60초는 그 조건에서 중단해 실행하지 않았다. 최종 결과는 `docs/evidence/v2/2026-10-24-auth-rate-retest/REPORT.md`에 있다.
